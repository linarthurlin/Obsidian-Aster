# Aster testing

npm run check validates TypeScript, plugin build, offline CSS, manifests, review engine, installer isolation, scoped retrieval, model-output boundaries and subprocess errors/cancellation/timeouts/output limits. DOM tests run the bundled plugin with mocked Obsidian and process APIs; CI does not call a live model.

The workbench test checks that loading filenames does not send note content, context must be previewed and explicitly approved, query changes reset approval, stale sources prevent sending, and closing the view cleans its DOM. It also creates a synthetic applied transaction, reconstructs a new plugin instance, lists the saved receipt, displays its exact diff and target hash state, and verifies rollback stays disabled until explicit approval. Chat tests cover custom Skill frontmatter and bounded local storage, slash expansion into visible editable text, retained user resources on deletion, the rule that Skill text grants no capabilities, current-note content copied from a synthetic active editor into a visible draft without sending or editing it, and scoped Corpus note/folder selection. Corpus search tests verify local-only search in a selected synthetic scope, bounded excerpts/results and a new-tab open; backlink tests use a synthetic Obsidian `resolvedLinks` map and prove that outside-Corpus sources are excluded without reading note bodies. Retrieval regression tests cover 12 lexical and 3 paraphrase cases across Traditional Chinese, English, mixed language, CJK phrase/space-split queries, body-only hits, same-basename distractors and long-note locators; they assert Recall@3, MRR, nDCG and exact excerpt locator validity, while preserving explicit misses for paraphrases with no shared terms. Folder fixtures verify exact two-note previews, reject a seven-note folder before reading bodies, respect the 24,000-character cap, and wait for explicit draft insertion. The settings-folder chooser test supplies synthetic folder metadata, excludes hidden paths, checks the saved scope, and confirms no note body was read. Deterministic Clear tests gate both transcript rename and Corpus preflight, then verify deletion waits for active sends, does not start Codex after Clear begins, leaves transcripts deleted, and rejects late stale writes. Knowledge workflow tests inspect a partially applied synthetic journal, recover only known after-state files, prove an unknown human edit blocks all recovery writes, and limit listing/review to matching Corpus receipts. Lifecycle checks verify no startup scan/model launch. Installer tests preserve existing plugin data and reject junctions.

Codex CLI 0.162.1 passed three small synthetic live cases: a supported update with evidence, source-instruction injection, and insufficient evidence. The update was applied and rolled back only in the synthetic corpus. These smoke cases do not establish statistical retrieval quality or adversarial robustness.

`node scripts/eval-retrieval.mjs` creates and removes a synthetic 313-file corpus under `.local/retrieval-eval`. Add `--near-limit` to benchmark 1,835 synthetic files and 18.99 MB with three representative queries. It compares the current substring ranker with a research-only `Intl.Segmenter` + BM25 candidate and reports Precision@3, Recall@3, MRR@5, nDCG@5, scan bytes, excerpt characters, and local latency. The runner has no Vault-path input, does not use real notes, and is not part of CI because latency is machine-dependent. Its hand-authored queries are an engineering comparison, not a representative relevance benchmark; serialized token payload is not a heap measurement, and the candidate ranker is not enabled in Aster.

A disposable Windows runtime smoke ran on 2026-10-18 with Aster 0.2.1 in Obsidian 1.14.4. The Vault, Electron user data, `APPDATA`, `LOCALAPPDATA`, and `USERPROFILE` were isolated under ignored `.local/aster-runtime-*`; the synthetic Markdown and generated one-page PDF were the only note sources. The plugin and commands loaded, the Codex `model/list` call returned seven model choices and thinking options without sending a model turn, six chat metadata records (with no sent turns) survived app reload, Project instructions were snapshotted into a new chat, a user Skill survived reload and expanded from the slash menu into editable text, and Quick Ask created an unsent draft from the selected synthetic passage. The host PDF.js helper extracted the marker from page 1 and Research Desk prepared an editable draft carrying the source digest. A final renderer reload observed no exceptions or `console.error`. Obsidian loaded its 1.14.4 package from the isolated update cache; the installed executable remained 1.13.7. No personal Vault was opened.

Follow-up PDF runtime checks used the updated Aster build in the same isolated profile. A generated four-page PDF selected at pages 2–3 produced only the two matching page locators and excluded page 1; selecting its blank page 4 displayed the OCR/Zotero no-selectable-text fallback. A generated 100-page PDF loaded through Obsidian PDF.js; a DOM observer clicked Cancel at the new first-page progress announcement, and the UI returned `PDF preview was cancelled.` with no evidence preview and Prepare Chat still disabled. A 1–20 selected-page run announced page 1, 10, and 20; progress messages are throttled to the first/last page and each tenth selected page. This verifies cancellation after PDF document load at a page boundary; the pending-`getTextContent()` race remains a deterministic synthetic test, not a real-worker claim. No model turn or personal Vault was involved.

Still pending in real runtime: streaming/cancellation and Clear during a live send, dynamic Corpus tools and protocol drift, app-server resume/compaction, transaction recovery, cache event and memory behavior, mid-`getTextContent()` PDF cancellation, scanned/image-only PDFs and 120/240-page boundaries, default/Halo/Orbit integration, keyboard/accessibility, and broader retrieval measurements. Synthetic tests do not establish those runtime behaviors. Historical monolith screenshots do not prove the current plugin runtime.
