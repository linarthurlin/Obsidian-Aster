# Aster testing

npm run check validates TypeScript, plugin build, offline CSS, manifests, review engine, installer isolation, scoped retrieval, model-output boundaries and subprocess errors/cancellation/timeouts/output limits. DOM tests run the bundled plugin with mocked Obsidian and process APIs; CI does not call a live model.

The workbench test checks that loading filenames does not send note content, context must be previewed and explicitly approved, query changes reset approval, stale sources prevent sending, and closing the view cleans its DOM. It also creates a synthetic applied transaction, reconstructs a new plugin instance, lists the saved receipt, displays its exact diff and target hash state, and verifies rollback stays disabled until explicit approval. Chat tests cover custom Skill frontmatter and bounded local storage, slash expansion into visible editable text, retained user resources on deletion, the rule that Skill text grants no capabilities, current-note content copied from a synthetic active editor into a visible draft without sending or editing it, and scoped Corpus note/folder selection. Corpus search tests verify local-only search in a selected synthetic scope, bounded excerpts/results and a new-tab open; backlink tests use a synthetic Obsidian `resolvedLinks` map and prove that outside-Corpus sources are excluded without reading note bodies. Retrieval regression tests cover 12 lexical and 3 paraphrase cases across Traditional Chinese, English, mixed language, CJK phrase/space-split queries, body-only hits, same-basename distractors and long-note locators; they assert Recall@3, MRR, nDCG and exact excerpt locator validity, while preserving explicit misses for paraphrases with no shared terms. Folder fixtures verify exact two-note previews, reject a seven-note folder before reading bodies, respect the 24,000-character cap, and wait for explicit draft insertion. The settings-folder chooser test supplies synthetic folder metadata, excludes hidden paths, checks the saved scope, and confirms no note body was read. Deterministic Clear tests gate both transcript rename and Corpus preflight, then verify deletion waits for active sends, does not start Codex after Clear begins, leaves transcripts deleted, and rejects late stale writes. Knowledge workflow tests inspect a partially applied synthetic journal, recover only known after-state files, prove an unknown human edit blocks all recovery writes, and limit listing/review to matching Corpus receipts. Lifecycle checks verify no startup scan/model launch. Installer tests preserve existing plugin data and reject junctions.

Codex CLI 0.162.1 passed three small synthetic live cases: a supported update with evidence, source-instruction injection, and insufficient evidence. The update was applied and rolled back only in the synthetic corpus. These smoke cases do not establish statistical retrieval quality or adversarial robustness.

`node scripts/eval-retrieval.mjs` creates and removes a synthetic 313-file corpus under `.local/retrieval-eval`. It compares the current substring ranker with a research-only `Intl.Segmenter` + BM25 candidate and reports Precision@3, Recall@3, MRR@5, nDCG@5, scan bytes, excerpt characters, and local latency. The runner has no Vault-path input, does not use real notes, and is not part of CI because latency is machine-dependent. This small hand-authored query set is an engineering comparison, not a representative relevance benchmark; the candidate ranker is not enabled in Aster.

Real Obsidian runtime testing, including transaction history/recovery behavior, close-during-cancel behavior, default-theme/Personal Glass integration, accessibility, and larger retrieval evaluations remain pending. Synthetic plugin reconstruction does not prove the actual Obsidian runtime. Historical monolith screenshots do not prove the current plugin runtime.
