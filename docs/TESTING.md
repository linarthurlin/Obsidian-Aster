# Aster testing

npm run check validates TypeScript, plugin build, offline CSS, manifests, review engine, installer isolation, scoped retrieval, model-output boundaries and subprocess errors/cancellation/timeouts/output limits. DOM tests run the bundled plugin with mocked Obsidian and process APIs; CI does not call a live model.

The workbench test checks that loading filenames does not send note content, context must be previewed and explicitly approved, query changes reset approval, stale sources prevent sending, and closing the view cleans its DOM. Chat tests cover custom Skill frontmatter and bounded local storage, slash expansion into visible editable text, retained user resources on deletion, the rule that Skill text grants no capabilities, current-note content copied from a synthetic active editor into a visible draft without sending or editing it, and scoped Corpus note/folder selection. Folder fixtures verify exact two-note previews, reject a seven-note folder before reading bodies, respect the 24,000-character cap, and wait for explicit draft insertion. The settings-folder chooser test supplies synthetic folder metadata, excludes hidden paths, checks the saved scope, and confirms no note body was read. A deterministic rename gate holds a transcript write while Clear runs, then verifies the file stays deleted and late stale writes are rejected. Knowledge workflow tests inspect a partially applied synthetic journal, recover only known after-state files, and prove an unknown human edit blocks all recovery writes. Lifecycle checks verify no startup scan/model launch. Installer tests preserve existing plugin data and reject junctions.

Codex CLI 0.162.1 passed three small synthetic live cases: a supported update with evidence, source-instruction injection, and insufficient evidence. The update was applied and rolled back only in the synthetic corpus. These smoke cases do not establish statistical retrieval quality or adversarial robustness.

Real Obsidian runtime testing, close-during-cancel behavior, default-theme/Personal Glass integration, accessibility, transaction history UI across restarts and larger retrieval evaluations remain pending. The journal recovery engine has synthetic CLI tests; this does not prove the Obsidian runtime flow. Historical monolith screenshots do not prove the current plugin runtime.
